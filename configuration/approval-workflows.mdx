---

The Approval Process lets staff request sign-off from an approver role before taking a sensitive action such as a refund or a ban. The request lives on the ticket and is decided in Discord or on the dashboard.

<Info>
  The Approval Process is an **Enterprise** feature. [Upgrade your plan](https://ticketcord.com/pricing) to access it.
</Info>

<Note>
  Multi-step approval chains are not yet available. The dashboard shows them as "Coming soon", and the bot only processes the single-step mode described here.
</Note>

## Setting Up

Go to **Dashboard → Bots**, pick your bot, choose the server, and open the **Approvals** tab.

| Setting | Description |
|---------|-------------|
| **Approver role** | The Discord role whose members can approve or reject requests |
| **Approval types** | Which of `refund`, `ban`, `policy_exception`, `escalation`, and `custom` may be requested (at least one) |
| **Custom types** | Up to 10 named custom types, used with `type:custom` |
| **Require reason** | Whether requests must include a reason (default on) |
| **Notify customer** | Whether the ticket creator is told about the decision (default on) |
| **Timeout** | Hours before an undecided request expires: 1 to 168, default 48 |
| **Audit log** | Optional Discord channel that receives every decision, with or without the reasons |

## Requesting Approval

Staff run the command inside the ticket:

```
/approval request type:<refund|ban|policy_exception|escalation|custom> [reason] [urgency] [amount] [custom_type]
```

- `urgency` is `low`, `medium` (default), or `high`
- `amount` is a number, useful for refunds
- `custom_type` names the custom type when `type:custom`

The approver role is pinged in the ticket. A ticket can hold one open request at a time.

## Deciding

Approvers act in Discord or from **Dashboard → Approvals** (and the approval pane on the ticket page):

```
/approval approve [reason]
/approval reject reason:<required>
/approval status
```

The decision is recorded on the ticket, announced in the channel, sent to the audit log channel if configured, and, when **Notify customer** is on, shared with the ticket creator.

## Statuses

| Status | Meaning |
|--------|---------|
| **Pending** | Waiting for a decision |
| **Approved** | An approver approved it |
| **Rejected** | An approver rejected it, with a reason |
| **Timed out** | Nobody decided within the timeout |

Nothing else happens automatically on a decision or a timeout; the outcome is informational.
