Auto-Route uses AI to read a new ticket and move it to the right category, notify the right staff, and tag it, based on rules you write in plain language.

<Info>
  Auto-Route is an **Enterprise** feature. [Upgrade your plan](https://ticketcord.com/pricing) to access it.
</Info>

## How It Works

1. A ticket is created
2. After the analysis delay, the AI reads the conversation
3. It picks the routing rule whose **instruction** best matches, if its confidence is above that rule's threshold
4. The rule's action runs: move the ticket, add tags, notify a role
5. If no rule matches, the fallback behaviour applies

## Settings

Open **Dashboard → Bots → your bot → Servers → the server → AI Features → Auto-Route**.

| Setting | Options |
|---------|---------|
| **Analysis mode** | First message, first three, first five, a custom count, or smart detection (default) |
| **Delay before analysis** | Default 30 seconds |
| **Fallback** | No action, move to a default category, or notify staff |
| **Staff notification threshold** | Confidence needed before staff are notified about a routing decision (default 80%) |
| **Custom instruction** | Extra guidance the AI applies to every decision |

## Routing Rules

Each rule has:

| Field | Description |
|-------|-------------|
| **Name** | For your reference |
| **Routing instruction** | A sentence describing which tickets belong here, for example "Questions about refunds, invoices, or failed payments". The AI understands it in every supported language |
| **Priority** | 1 to 100; tells the AI which rule to prefer when several could apply |
| **Confidence** | Minimum confidence for this rule to fire |
| **Action** | Move to a category, or add to a queue |
| **Notify staff** | Optionally mention a staff role |
| **Add tags** | Tags to apply |
| **Allowed staff roles** | Restrict who can see the routed ticket |

<Note>
  Older rules may still use keyword, topic, sentiment, urgency, or language triggers. They keep working, but add an instruction to upgrade them.
</Note>

## Templates

Start from a template and adjust the categories:

- **E-commerce Store**: order and shipping issues, payment and billing, product questions, returns
- **SaaS Platform**: bugs, feature requests, technical issues
- **Gaming Community**: general inquiries, reports, applications
- **General Support**: a neutral starting point

## Tips

- Write instructions the way you would brief a new team member.
- Give the most specific rules the highest priority.
- Use the fallback to catch tickets that match nothing.
